# rapidgzip: a cut stream delivers what the standard library delivers

_Requested by **davi** · [project thread](https://claude.ai/code/project/chan_01DbMk7aw1GQgNkBfBSYo2X2?thread=cmsg_01DbMk7aw1GQgNkBfBSYo2X2Y6PTZnUPyaDN8icJgcPink)_

Before: reading a truncated gzip, zlib or raw DEFLATE stream through rapidgzip could return far fewer bytes before the error than the standard library returns. rapidgzip decodes ahead in worker threads, and 0.16 aborts the child process as soon as one of them reaches the chunk that holds the cut. Everything those threads had decoded past the reader was lost with the child. Measured on 4 cores with a 154 MB gzip: cut at 10 %, `use_rapidgzip=ON` delivered **0 bytes**, where the standard library delivered 20.3 MB. Cut at 35 %, it delivered 56.6 of 70.9 MB. The loss grows with the thread count: with 16 threads, a cut near the end lost about 40 MB of 202. The bytes that did come back were always correct.

After: a cut stream delivers exactly the standard library's bytes and then raises its `TruncatedError`. It is still about 3x faster than the standard library, and reading a whole file is as fast as before.

When the child crashes, the read is handed to the standard library, as a data error that rapidgzip reports already was. The standard library starts at the last checkpoint the reader passed, not at the start of the stream. A checkpoint is a DEFLATE block boundary from rapidgzip's index, plus the 32 KiB of output before it.

How:
- **`deflate_resume.py` (new):** zlib resumes at a block boundary. The window goes in as a preset dictionary (`zdict`). Python's `zlib` has no `inflatePrime`, so the decoder cannot start mid-byte. To reach the block's bit offset, the input starts with made-up empty DEFLATE blocks whose length in bits ends that many bits into a byte. The rest of the input is the source unchanged.
- **Checkpoint tracking:** `RapidgzipChildStream` keeps a checkpoint. A new `POINTS` request asks the worker for the index points around the output. The parent takes each window from the output it already received. To keep the cost of these queries negligible, a query is made only after the output passes the point the last query named, and at most once per 4 MiB or per 16 KiB times the index size.
- **Takeover:** `_StdlibOnAcceleratorError` now also takes over on a child crash, in a read or a seek, and starts from the checkpoint. The gzip path with a container-declared size now goes through it too.
- **Checksums:** a resumed decode that reaches the end of its DEFLATE stream cannot check the CRC-32 or Adler-32 that follows, because it never saw the output before the checkpoint. It raises `ResumeReachedStreamEnd`, and the standard library starts over from the start of the stream, which checks it.
- **Worker:** it skips the last point of a complete index, which is the end of the data and not the start of a block.
- **Spec and docs:** updated through an OpenSpec change, archived in this PR. `dev-docs/known-issues.md` Bug 4 now records the one-line upstream fix that ends the abort: catching the throw from `seekTo` in `GzipChunk.hpp`, tested on a source build. It has not been filed upstream.

Benchmarks: archivey's gzip codec stream, best of 5 runs, 4 CPUs, a 202 MB file that compresses to 154 MB.

| case | stdlib | rapidgzip before | rapidgzip after |
| --- | --- | --- | --- |
| whole file, 1 MiB reads | 1.23 s | 0.32 s | 0.32 s |
| 220 seeks with 64 KiB reads | 12.7 s | 0.41 s | 0.40 s |
| cut at 10 % | 0.12 s, 20.3 MB | 0.04 s, 0 bytes | 0.18 s, 20.3 MB |
| cut at 60 % | 0.73 s, 121.6 MB | 0.18 s, 103.8 MB | 0.30 s, 121.6 MB |
| cut at 99.9 % | 1.27 s, 202.4 MB | 0.32 s, 198.2 MB | 0.37 s, 202.4 MB |

Whole-file reads in 16 KiB pieces: over 10 interleaved runs the medians were 0.36 s after and 0.35 s before. A first version queried every MiB and copied up to a MiB per checkpoint, which cost about 10 %. Both were fixed before this push.

Tests:
- **`tests/test_deflate_resume.py`:** the resumed decoder at all 8 bit offsets, with a window the stream refers back into. Cut and whole streams are compared against zlib decoding from the start, and seeks are checked through a checkpoint.
- **`tests/test_rapidgzip_resume.py`:** for gzip, zlib and deflate, from a path and from a file object, cut streams deliver the standard library's bytes and error. Every checkpoint reproduces the payload. A crash in a two-member gzip resumes in the first member, then starts over at that member's end. A CRC-damaged member with bytes after it gets the same error type as with the standard library.
- **`test_a_child_death_is_reported_by_how_it_ended`:** now checks the child stream itself. Two new tests cover a crash that the standard library reads on past, and a SIGKILL or SIGTERM that still ends the stream.
- **The large cut-stream test** (the one PR 542 made deterministic) is renamed `test_a_large_cut_stream_delivers_what_the_standard_library_delivers`. It now compares the whole result with zlib byte for byte, for gzip, zlib and raw DEFLATE. How much the child returns before the abort no longer changes what the caller gets, so the race that made it fail now and then cannot affect it. This replaces PR 542's change.
- `./scripts/check.sh` passes. `./scripts/test.sh --all-configs` passes all three legs: [all] 8577 passed, [all-lowest] 8577 passed, [core-only] 6093 passed.
