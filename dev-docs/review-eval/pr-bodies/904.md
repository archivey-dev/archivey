# Run native decoders in child processes behind ArchiveyConfig.process_isolation

_Requested by **davi** · [project thread](https://claude.ai/code/project/chan_01DbMk7aw1GQgNkBfBSYo2X2?thread=cmsg_01DbMk7aw1GQgNkBfBSYo2X2JM8BRYfdEuDXrYTBm6nMYb)_

Before: rapidgzip and PPMd members over 16 MiB decode in child processes. Every other native decoder (`zlib`, `bz2`, `lzma`, zstd, `lz4`, `brotli`, `inflate64`, and smaller PPMd members) runs in the caller's process. No setting changes either side.

After: `ArchiveyConfig.process_isolation` takes a `ProcessIsolation` value:
- `KNOWN_CRASHES` is the default. It runs rapidgzip and **every** PPMd member in a child, because small members can crash pyppmd in-process too: the crash comes on the decode that stops a worker after an early end.
- `NATIVE_DECODERS` runs every native decoder in a child, detection probes included.
- `NONE` runs everything in-process. The docs discourage it. Under `NONE`, rapidgzip is not used, and `use_rapidgzip=ON` is refused.

AES and checksums stay in the caller's process. The security page has a new section on this setting and a recipe for running the CLI in a subprocess with a timeout.

How:
- **Shared worker.** One generic worker, `codecs/decoder_worker.py`, is keyed by codec name and never imports archivey. The PPMd and rapidgzip children share its framing and error payload; rapidgzip keeps its own messages.
- **Pool.** Each open decoder takes a child from a pool of reused idle children, with at most four idle. A child serves at most 64 decoders, and is reused only after a clean finish. A PPMd child is not reused after:
  - an early end;
  - a check-value mismatch, including one raised by the member stream above the decoder, solid 7z folders included;
  - a refusal;
  - the quiesce decode, including an abandoned read.
- **Crashes in a reused child.** A crash or error there is not charged to the member. The member re-runs in a fresh child from a record of up to 1 MiB of input. A request that would take the record past 1 MiB moves to the fresh child before it is sent. During the re-run, each reply's output is checked against the CRC-32 of the output already returned, and if the fresh child's output differs, the call raises `ReadError`. Only the fresh child's verdict counts. If a fresh child cannot start or cannot allocate at that point, the caller gets the same `ResourceLimitError` as at open.
- **PPMd input stays whole.** Input up to `max_ppmd_in_process_input` is still held and handed over whole, in the child too. Fed in pieces, pyppmd 1.3.1 stops about 28 KiB short on some valid members; one is pinned in `tests/test_process_isolation.py`. Members over the limit still hit that bug, as they do on main (tracked internally).
- **Prompt release.** Decoders give their child back at `close`, so a reader caught in a reference cycle does not keep its children leased until GC runs. A process created by `fork` never writes to its parent's children, and a call on a decoder it inherited raises `ArchiveyUsageError`.
- **Tests.**
  - Every corpus fixture, and every codec 7z can write (Deflate64, PPMd, BZip2, LZMA, BCJ, Delta), must read byte-exact under all three values.
  - `tests/test_decoder_child.py` covers reuse, the poison A/B case, blame, death classes, the 64-decoder quota, the move past the replay limit, a re-run that disagrees with output already returned, start failures during the move, and fork.

Spec and design: archived as `openspec/changes/archive/2026-10-20-native-decoder-process-isolation/`, with its deltas applied to `openspec/specs/`.
