# TAR: native header parser and walker (not wired in yet)

_Requested by **davi** · [project thread](https://claude.ai/code/project/chan_01DbMk7aw1GQgNkBfBSYo2X2?thread=cmsg_01DbMk7aw1GQgNkBfBSYo2X2Tz5XhkrVJdCCNnZvM42kkt)_

**Before:** archivey reads TAR headers only through stdlib `tarfile`, using the hooks and private-method overrides that the design in #736 lists.

**After:** archivey has its own TAR header parser and walker in `internal/backends/tar_parser.py`. Nothing uses it yet: the TAR reader still goes through `tarfile`. This is stage 2 of the five-PR plan in #736. The reader switches to the new parser in stage 4, after #704 and #716 merge (#706 has merged).

What it reads:
- v7, POSIX ustar (with `prefix`) and old GNU header blocks, with signed and unsigned checksums and with octal and GNU base-256 numbers.
- PAX records, per member (`x`, Solaris `X`) and global (`g`). Length checks are strict and `hdrcharset` follows the POSIX scope. An empty global value deletes the key.
- GNU long names and long link names.
- All four GNU sparse encodings: old GNU `S` with extension blocks, and PAX 0.0, 0.1 and 1.0.
  - The records that define each PAX map choose the encoding: `GNU.sparse.map` for 0.1, `GNU.sparse.size` or a `GNU.sparse.offset` record for 0.0, and `GNU.sparse.major` or `GNU.sparse.realsize` for 1.0. Any major of 1 or more reads as 1.0, as GNU tar 1.35 reads it.
  - These are `CorruptionError`: a sparse record with an empty value, a 0.0 member with no `GNU.sparse.size`, a `GNU.sparse.realsize` with no major, and a major that is 0, empty or not a number. A `GNU.sparse.minor` alone makes no sparse member.
  - The 1.0 map is read during the walk, from the start of the data area. A bad map fails the listing and counts against the member's budget, as in the other encodings.
  - Sparse records on a type without a data area make no sparse member.

How it bounds the work:
- The walk is a loop, so header chains cannot recurse.
- Each member's extended headers and sparse map draw on one budget, `max_metadata_bytes`, the same rule as #704. The budget is charged before anything is read or parsed.
- A forward-only walk reads through skipped data in 64 KiB steps and stops at the first short read.
- Global records are one shared snapshot until a `g` header changes them.
- A sparse number past the largest file offset is `CorruptionError` in every encoding. In an old GNU header block it rejects the block, on either side of zero.
- After an error, `next_entry` raises the same error on every later call.

`TarEnd` gives the offset where the walk stopped and the reason, as a `TarEndKind`: zero block, rejected, absent or short. The reader needs this for its EOF policy, so it no longer has to infer it. The cases:
- An x or L header right before the end-of-archive marker ends the walk at the zero block. GNU tar lists such archives cleanly. The `TarEnd` reason names the unused header, so the reader can warn about it.
- A `g` header starts no chain.
- These all end the walk as a rejected header: an extended-header chain followed by a block that is no header, PAX records that do not parse, and a bad number in an old GNU extension block.

**How:** where GNU tar and `tarfile` disagree on a malformed archive, the parser follows GNU tar (DR-6), and each case has a comment:
- PAX wins over a GNU long name, whichever comes first.
- The ustar `prefix` is joined only under ustar magic. As a result, GNU tar's incremental archives, which store the atime where `prefix` would be, list as `d/f.txt`, not `15262452373/d/f.txt`.
- A dangling x or L header before the end marker is a clean end.

Which types carry a data area follows `tarfile`, so no other listing changes (DR-5). `validate_sparse_map` keeps #716's rules and also checks the exact stored size. GNU tar 1.26 to 1.35 and bsdtar write the exact sum in every encoding, so a gap of 1 to 511 bytes is damage (DR-1, DR-3; the maintainer chose this).

**Tests:**
- `tests/test_tar_parser.py`, 123 cases: numbers, checksums, layouts, PAX framing, each sparse parser with its budget and range refusals, map validation, sparse versions and how each is detected, walk ends (dangling extended headers included), rejected chains, the failed-walk rule, truncation in both modes, chain budgets, global records, name precedence, the old-style directory rule, types without a data area, and forward-only data streams.
- `tests/test_tar_parser_differential.py`, 21 cases, skipped without GNU tar. They cover every corpus TAR entry, `tarfile`'s ustar/GNU/PAX output, and GNU tar archives in `gnu`, `oldgnu` and `posix` formats, in PAX sparse 0.0, 0.1 and 1.0, and in incremental mode. Each one is listed field by field and read byte by byte against `tarfile`, seekable and forward-only.
- `tests/fuzz_tar_parser.py`, env-gated like the RAR and 7z harnesses. The seeds are plain archives, crafted archives in every sparse encoding, and GNU tar's sparse archives where GNU tar is installed. Mutations re-sum header checksums and can write map separators. The harness catches two reverted fixes:
  - With the sparse range checks removed, it fails with `OverflowError`.
  - With the one-number-per-record rule for PAX 0.0 reverted, it fails on the pair assertion.
- `./scripts/check.sh --fix`, `./scripts/test.sh` (10 894 passed after merging main) and `scripts/review_prep.py` pass.
